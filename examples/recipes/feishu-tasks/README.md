# 飞书私聊和群内 @ 下任务

给机器人发自然语言需求，先整理、补充和确认，再交给现有项目规则。此入口不改变内核协议，不自动创建项目，也不从聊天文字接受路径、Agent、权限或命令。

## 使用

可在 `tasks` 启用 `modelRouting: true`。明确的确认、取消、状态、帮助、归档及标准提醒/改期由程序直接处理，不调用模型；澄清问题中的“确认”仍需理解补充内容。其他授权消息交给首选模型理解，首选失败再尝试候补。私聊带上同一会话、同一发送人最近八轮已回复的交流，包括任务、提醒、状态和个人聊天，每条用户内容最多 1200 字、回复最多 1600 字。闲聊、查看图片和普通问答直接回复，查任务和登记一次性提醒由程序完成。项目任务先给摘要和验收条件，确认卡绑定原发送人和当前版本，只有真实确认才会触发规则。若希望确认后直接开发，把可信规则指向登记的 Codex 开发接单程序。

每个项目任务和提醒有稳定编号。用户可以引用事项消息，或通过名称指定要查的事项。模型从同一发送人在当前会话的事项中选择，程序按原消息和卡片的真实关联复核，查询中台的最新轮次后再回答。事项状态和待发送回执沿用飞书入口的本地事务记录，旧记录无需迁移。独立的本机看板可使用只读事项投影，展示本人私聊中的进度、提醒改期和最近一次模型处理状态。

私聊机器人：

> 给命令面板组件库新增 ShortcutHint 组件，支持按键数组和 className，补充使用示例并确保构建通过。

机器人会回复带“确认”“取消”按钮的卡片，列明项目、类型、任务摘要与验收条件。点击“确认”开始执行，点击“取消”结束待确认任务。模型识别“就按这个开工吧”等口语确认或取消时，只提示操作原卡片或发送明确指令，不直接改变任务；缺资料时继续展示待答问题。按回复中的 `确认 任务号` 开工；也可回复补充意见或 `取消 任务号`。`状态 任务号` 查询已记录状态，`帮助` 查看项目目录。

群内先把机器人加入群，每条请求及补充都需明确 @ 当前机器人。确认指令带任务号，或回复原任务消息并 @；不带任务号、没有回复上下文的“确认”不会执行。仅配置的发送人能派活，同一个人的任务也按群和私聊隔离。

初始澄清可在原消息下继续补充；单一私聊中只有一个待确认任务时也可直接补充。存在多个待确认任务时请回复对应消息。任务派发后，开发 Agent 的进一步提问仍走现有飞书私聊卡片；执行轮次结果回复到最初的任务消息。`cancelled` 回执写“本轮已结束”或“验收已结束”，同时保留摘要与错误原因；不把失联结案说成进程已停止，也不把一轮结束说成已合并或上线。

### 验收、取消和闲聊

“只验收当前 main 的 SDK 平台数据库迁移，保留现有代码”会生成验收卡。项目的 `events.verify` 指向专用规则，`verifyBranch` 显示登记的目标分支。Codeup 的配置生成器生成这条规则：接单程序取目标分支提交，用临时 worktree 运行登记的检查和可选的独立 MySQL 迁移测试，然后清理工作区并回报结果。验收入口没有开发、提交或创建 MR 的步骤。原有三种开发类型继续沿用原规则；未登记验收的项目会提示配置。

私聊只有一项待办时可说“取消该任务”；有多项时回复对应卡片，或说“取消 任务号 任务”。待补充时回答“确认”可以补全摘要，随后确认卡片才开工。告别、问候和表达心情按本条消息回复，不写入任务摘要，也不改变卡片或执行状态。

私聊里即使有多项待办，也可以直接回答刚问的问题，比如只发项目名。要补充更早的任务，可以回复那张卡片或原消息。

同一私聊里提出独立的新需求，会生成单独的任务号和确认卡。项目和目标说清即可，脚手架入口、目录、命名规范由执行时查仓库；可以直接说“英文名你来起”。

### 一次性提醒

私聊可发“周一待办，记得提醒我”，换行列出待办，或直接发“明天 09:30 提醒我确认上线时间”。未写几点时按本机时区的上午 9 点安排。机器人会先确认日期时间，到点回复原消息。提醒不需要登记项目，也不派发开发任务。关机或断网时，服务恢复后会继续发送到期提醒。

回复原提醒或排程回复说“改为 10 点吧”，可修改尚未发送的提醒时间，原日期与清单继续沿用。只有一条待发送提醒时可以直接说。多条无法区分时，机器人会请你回复具体一条。

### 清理历史任务

本人私聊可以用「清理历史任务」生成归档预览。点击卡片的「确认归档」后，当前会话已结束或取消的任务会从日常列表和只读看板隐藏，原有记录可恢复。提醒及尚未结束的任务会保留，停止运行中的任务需使用中台现有停止操作。执行结果会回复到原请求，回复失败可续发。输入「恢复归档 归档编号」可恢复指定批次，也可用「撤销归档」恢复最近仍有效的一批。

普通聊天中出现的操作承诺不代表执行。机器人以已保存的执行状态或真实回执回答清理进度，缺少可跟踪记录时会明确说明。

## 飞书设置

安装并配置官方 `lark-cli`，完成本人登录。机器人需接收私聊消息、群内 @ 消息、发送和回复消息的相应权限；在开发者后台订阅并发布 `im.message.receive_v1`，原卡片入口继续使用 `card.action.trigger`。可先用 `lark-cli event consume im.message.receive_v1 --as bot --dry-run` 检查前置条件，不能对已在线应用再开第二个卡片监听。

消息消费和卡片消费复用同一个官方事件总线与 WebSocket；不需要公网回调地址。群内 @ 权限应按飞书开放平台实际提示配置，不申请所有群消息读取权限。

## 中台配置

1. 在 `rules.json` 的 `sources` 登记 `feishu-chat`。
2. 为它生成独立来源密钥，留在私有 `config.json`：`agent-autoloop key new source feishu-chat`。这是接入配置的一部分，先获得用户的接入授权。不得复用本人或通道密钥。
3. 在 `config.json` 原有 `channels.feishu` 下加入 `"use": "feishu-tasks"`，并加入以下 `tasks`。保留原来的 `key`、`user` 和 `lark`。

```json
{
  "url": "http://127.0.0.1:3350",
  "sourceKey": "该来源自己的密钥",
  "bot": "ou_机器人自己的open_id",
  "senders": ["ou_允许派活的本人"],
  "parser": { "use": "dsh", "program": "/已有的dsh启动脚本" },
  "projects": [{
    "id": "palette",
    "name": "命令面板组件库",
    "aliases": ["syca-command-palette", "组件库"],
    "events": {
      "feature": "palette.feature",
      "change": "palette.change",
      "bug": "palette.bug"
    }
  }]
}
```

可选 `groups: ["oc_允许的群"]`：省略时接受白名单发送人在机器人所在群中的明确 @；空数组则禁止所有群。`bot` 可以用 `lark-cli api GET /open-apis/bot/v3/info --as bot` 核实。不要用应用 App ID 代替机器人 open_id。

省略 `parser` 时默认用已登录的 Codex。指定其他首选且希望缺少工具时转给 Codex，可配置 `"parser":{"use":"dsh","fallbacks":[{"use":"codex"}]}`。显式候补决定允许处理聊天资料的模型。解析器支持 `dsh`、`agy` 和 `codex`，可指定 `program`、`model`、`effort`。DSH 的模型由 DSH 自己配置。可在 `parser.fallbacks` 按顺序填入其他解析器，例如 `[{"use":"agy"},{"use":"codex"}]`。首选启动失败、超时或结果无效时依次尝试候补，下条消息重新从首选尝试。图片走支持图片的 DSH 或 Codex。每次解析使用只读权限，120 秒超时。聊天资料在临时文件中，提示词只引用文件位置。模型只返回候选摘要，程序验证项目和类型，人确认后才发送可信映射中的事件。

4. 为每个项目配置匹配 `feishu-chat` 来源及三个事件类型的开发规则。`cwd`、`to`、权限和执行规范仍只写在可信规则中。和已有手动入口使用相同 `group`、`parallel: 1`，避免同一工作目录并发修改。
5. 运行 `agent-autoloop check`，再重新加载服务。开发规则没有匹配或被暂停时，会明确回复未派发。

本地持久状态默认在 `AGENT_AUTOLOOP_HOME/feishu-tasks.db`；可用 `tasks.database` 指定私有目录中的文件。它保存原消息、确认摘要、派发记录与回复状态，含业务资料，不能提交到仓库。事件使用原始 `message_id` 去重；回复使用稳定的飞书幂等键。重启后恢复待处理工作，解析失败会通知用户，不自动反复调用模型。

## 验证

先运行 `tests/feishu-tasks*.test.ts`，这些测试只用临时数据库、假 CLI 与本地 HTTP。真实账号仅在用户授权后验收：私聊、群内 @、摘要确认、开发规则收到事件和原消息收到结果分别核实；未实际验收的步骤要写清楚。

## 当前范围

- 输入支持文字和富文本。模型入口还可读取单张图片，或按文字问题读取同一发送人在当前会话中引用的、机器人已收到的原图。飞书机器人要有消息资源权限，解析器需支持图像。其它文件请附参考链接并说明需求。
- 解析使用所配置 Agent 的模型服务，会消耗其额度；解析器用量目前不计入中台开发轮次的 Token 汇总。
- 为保持确认顺序，同一聊天/发送人的消息按顺序处理。原消息永久不可回复（例如已撤回或机器人被移出群）时，该聊天的待回复记录会持续重试，需要管理员处理；不会阻塞其他聊天。

确认卡片绑定发送人、卡片消息和摘要版本，只有原发起人可操作。修改摘要后旧卡片失效；重复点击不会重复派发。已派发或取消后卡片移除按钮并更新状态。已有文字草稿会补发按钮卡，不重新调用模型或启动开发；原文字指令继续可用。

同机运行 Codeup 插件时，可在 `tasks.delivery` 配置 `registry`（可信项目登记文件绝对路径）、`envFile`（含登记令牌变量的本机文件绝对路径）和 `source`（飞书入口来源名，例如 `feishu-chat`）。服务从本机中台和开发记录关联任务，在已合并时只读核实云效的 MR、同一提交的 CI 与独立 CR。已确认的原卡和「状态 任务号」显示同一份结果。旧单随服务启动补齐；核实失败时显示待核实并重试。配置了部署的 Codeup 项目在合并后继续展示 Flow 运行号，发布需要处理时显示原因，交付插件核实版本后才显示“部署版本已核实”。

## 消费、提醒与本机管理

明确确认、取消、状态、帮助、归档和标准提醒优先走本地处理；普通消息先加处理中 Reaction，回复持久化后移除，移除失败单独重试。同一聊天与发送人按序处理，最多四个会话并行且轮转服务；提醒、交付结果维护独立于慢模型。改期和到期发送并发时按提醒时间核对回执，不覆盖新的时间；新时间使用独立发送标识。已发起的旧提醒可能仍在途中。

私聊保留同一发送人最近八轮已回复上下文，包含主动发送的本人通知；指定项目名补充当前草稿，不新建重复任务。`tasks.timezone` 可设 IANA 时区，未指定沿用本机时区；12 小时制和无效改期会被校验。

本机看板默认可管理，仅允许已配置本人的私聊草稿取消；有待提交事件的草稿不能取消。取消标记持久化，旧模型回写不能恢复它。交付状态通过来源事件接口、本人状态与 why 接口核验；暂停回答必须属于当前轮次，不直接读取中台数据库。已完成的交付不再轮询。

### 解析器与可选能力

`parser` 和每个 `fallbacks` 条目可加 `credentials: ["自定义环境变量名"]`，只给该候选放行。默认保留 DSH 的 `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` / `DSH_HOME`，Codex 的 `OPENAI_API_KEY` / `CODEX_API_KEY` / `OPENAI_BASE_URL` / `CODEX_HOME`，agy 的 `GEMINI_API_KEY` / `GOOGLE_API_KEY`，以及标准代理和语言环境；业务服务密钥不会整批继承，`AGENT_AUTOLOOP_*` 不可放行。CLI 仍可使用原有账号配置。

未配置 personal 或 delivery 时不加载对应模块。个人通知只关联本人和指定规则；默认规则名是 `private morning`、`private care`、`private 巡检`。自行改名时设置 `tasks.personal.rules` 数组，标题不用于授权。
