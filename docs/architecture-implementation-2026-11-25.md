## 本批范围

落实已确认缺陷与插件边界两部分。保留纯内核、现有插件发现方式、零运行时依赖、默认本机管理可写；新增功能优先通过可信配置和局部插件接口连接。本批不拆仓、不引入全局 hook、工作流引擎或新数据库框架。

## 以后怎样接新功能

1. 事件来源、执行器和通知平台仍放在 `plugins/<name>` 的三个既有入口。
2. 项目、路由、权限、模型候补和通知规则写在可信配置；外部文字只作为资料。
3. 业务插件拥有私有状态及公开查询/操作接口，其他插件不拼接它的表结构、存储键或 HTTP URL 来猜阶段。组合入口只在配置启用时加载能力。
4. 队列、重派、并发与事实仍归中台。局部接口必须明确证据、失败与再次调用语义，不把业务步骤塞进内核。
5. 只有出现第二个真实调用场景且局部接口无法承载时，再讨论共用抽象。已有公共协议新增可忽略字段，删除或改义按版本约定执行。

## 审查与取舍

- Codex 独立审查实际工作树与开工快照，找到并修复：卡片对象身份丢失、默认模型认证变量被过滤、认证首页缓存；后续修复再次只读复审通过。
- Gemini 通过 agy 成功返回，修复：登录页面缓存、脚本未就绪时原生表单可能泄露密钥、残留会话锁住本人、退出重试复用失败状态。
- DeepSeek Harness 通过 dsh headless 成功返回，修复：可选模块异步加载时卡片处理器尚未就绪。其他意见逐项核实：来源插件的抛错表示拒绝请求是既有契约；refs/cards 在当前写入方只追加；开发上下文由另一条可信执行路径读取；MR 创建已有持久意图、查找与读回；登录静态文件与 CSP 已由浏览器验证。
- 飞书附加个人续聊记录是可降级信息，失败记录日志，不谎报远端发送失败；本批没有为此增加通用补偿队列。
- worker 完成后完整读取解决了已复现的结果截断，但不是任意大日志的资源上限方案。超大输出的流式适配属于后续接口评估，不宣称无限容量。

## 兼容与未做事项

核心事实格式、投影重建、/v1 和插件发现路径未变。个人失败次数保存在插件自己的新增表，旧记录继续使用；既有模型账号配置保留，非标准认证环境变量通过 credentials 显式登记。自定义个人规则名需列入 tasks.personal.rules，不能依赖通知标题匹配。登录收紧的是看板入口；登录后仍默认可写，--readonly 保持强制只读。
